# AnyRouter Admin

AnyRouter Admin 是一个支持多平台的账号管理与自动签到面板。除了默认的 AnyRouter 平台外，也可以为其它兼容平台单独配置接口路径，统一管理账号、签到、额度、Token、节点状态和消息推送。

部署方式见 [DEPLOY.md](DEPLOY.md)。

## 功能特性

### 平台管理
- 支持新增、编辑、删除多个平台
- 可为每个平台单独配置签到方式，以及 `base_url`、`sign_api`、`checkin_api`、`user_api`、`models_api`、`groups_api`、`token_api`、`status_api`、`console_url`
- 支持同步和查看平台 API 节点
- 首个创建的平台会自动设为默认平台
- 删除默认平台后，会自动将最早创建的剩余平台提升为默认平台
- 添加账号时会默认选中默认平台

### 账号管理
- 支持按平台集中管理多个账号
- 支持批量导入账号
- 支持本地分组管理
- 支持启用、禁用、编辑、删除账号
- 支持单账号和批量健康检查
- 支持批量签到、批量启用/禁用、批量迁移平台、批量调整分组
- 实时同步账号额度、已用额度、请求数、邀请返利等信息
- 账号页首屏进入会先显示加载状态，避免在数据返回前误显示为空账号

### 签到与额度统计
- 支持单账号签到、批量签到、定时自动签到
- 支持签到失败重试和完整签到日志
- 兼容两类签到额度来源
- 旧平台可直接使用签到接口返回的奖励额度
- 新平台可通过 `checkin_api` 查询月度签到记录，并从 `quota_awarded` 中提取当天签到额度
- 登录即签到平台可在平台配置中将签到方式设为“登录即签到”，系统会在每次签到时强制登录一次，并按登录响应或登录前后余额差值记录奖励
- 单账号签到、批量签到、自动签到和重试签到后会自动同步最新额度缓存，无需手动刷新账号页才能看到剩余额度和已用额度变化
- 仪表盘支持汇总总额度、今日签到结果、请求数等数据

### API Token 管理
- 支持查看、同步、创建、编辑、删除账号 Token
- 支持复制完整 Token
- 支持展示剩余额度、已用额度、模型限制、分组等信息

### 模型、分组与状态
- 支持同步模型列表
- 支持同步账号所属分组
- 支持读取状态接口并展示节点状态结果

### 运维与审计
- 支持在设置页直接导出和导入备份
- 支持查看和导出审计日志
- 支持查看、筛选、下载、清空系统日志

### 系统设置
- 支持自动签到时间配置
- 支持健康检查和失败重试参数配置
- 支持为后端访问目标平台配置独立 HTTP/HTTPS 代理
- 支持在设置页分栏管理常规配置、通知渠道、分组、备份、审计日志和系统日志

### 消息推送
- 支持 PushPlus、企业微信、钉钉、飞书、SMTP、微信公众号
- 支持渠道新增、编辑、删除、启用、禁用和测试发送
- 支持按账号绑定签到推送渠道

### 交互与效率
- 支持顶部通知中心和全局 Toast 提示
- 支持命令面板快速搜索账号、平台、签到日志并执行常用动作
- 支持键盘快捷键、当前视图刷新和快速修改密码

## 快速开始

### 默认平台

系统首次启动时会自动创建默认平台 `AnyRouter`。如果你要接入新的兼容平台，可在「平台管理」中新增平台并填写对应接口路径。

### 添加账号

添加账号需要提供以下信息：

| 参数 | 说明 | 获取方式 |
|------|------|----------|
| User ID | 用户标识 | 请求头中 `new-api-user` 的值 |
| Session Cookie | 会话凭证 | Cookie 中 `session` 的值，可选 |
| 登录账号 | 自动登录账号 | 平台登录邮箱或用户名，可选 |
| 登录密码 | 自动登录密码 | 平台登录密码，可选 |

说明：
- `Session Cookie` 和 `登录账号 + 登录密码` 二选一即可
- 如果平台的 `session` 每天会刷新，建议直接保存登录账号和密码，系统会在 `session` 失效后自动登录并回填新的 `session`

获取步骤：
1. 登录目标平台控制台
2. 打开浏览器开发者工具
3. 切到 Network 选项卡
4. 刷新页面并打开任意一个接口请求
5. 在请求头中找到 `new-api-user`
6. 在 Cookie 中找到 `session`

### 新平台签到额度适配

如果目标平台的签到接口只返回签到结果，不直接返回奖励额度，请在平台配置中填写 `checkin_api`。系统会按月份请求该接口，并从签到记录中的 `quota_awarded` 提取当天的签到奖励。

例如：

```json
{
  "data": {
    "enabled": true,
    "stats": {
      "checked_in_today": true,
      "records": [
        {
          "checkin_date": "2026-04-10",
          "quota_awarded": 9989789
        }
      ]
    }
  },
  "success": true
}
```

更完整的字段映射说明见 [docs/new-platform-response-adapter.md](docs/new-platform-response-adapter.md)。

### 平台接口字段

| 字段 | 默认值 | 用途 |
|------|--------|------|
| `base_url` | 平台自定义 | 平台根地址 |
| `sign_api` | `/api/user/sign_in` | 执行签到 |
| `checkin_api` | `/api/user/checkin` | 查询月签到记录和奖励 |
| `sign_mode` | `api` | `api` 表示调用签到接口，`login` 表示登录即签到 |
| `user_api` | `/api/user/self` | 获取账号详情 |
| `models_api` | `/api/user/models` | 获取模型列表 |
| `groups_api` | `/api/user/self/groups` | 获取平台分组 |
| `token_api` | `/api/token/` | 获取和管理 Token |
| `status_api` | `/api/status` | 获取状态或节点信息 |
| `console_url` | `/console` | 平台控制台地址 |

## 系统设置

在「系统设置」页面可以统一配置以下内容：

- 自动签到时间
- 健康检查开关和间隔
- 签到失败重试次数和重试间隔
- 后端平台代理开关与代理地址

### 实时刷新说明

- 账号页、账号详情页和仪表盘会通过 SSE 事件流自动刷新签到和健康检查结果
- 签到完成后，系统会先同步账号缓存额度，再推送页面刷新事件
- 命令面板执行的一键签到、批量健康检查等动作也会复用同一套刷新链路
- 如果你升级后端后页面行为仍是旧版本，请同步重新构建并发布前端

### 后端平台代理说明

- 环境变量名称仍为 `ANYROUTER_PROXY_ENABLED` 和 `ANYROUTER_PROXY_URL`
- 代理仅作用于后端访问目标平台的请求
- 账号验证、签到、Token 同步、模型列表、分组查询、状态查询等都会走该代理
- 目前支持 `http://` 和 `https://` 代理地址
- 如代理需要认证，可填写完整地址，例如 `http://user:password@127.0.0.1:7890`

## 推送渠道配置

### PushPlus

| 参数 | 说明 |
|------|------|
| Token | PushPlus 的推送 Token，在 [pushplus.plus](https://www.pushplus.plus/) 获取 |

### 企业微信

| 参数 | 说明 |
|------|------|
| Webhook URL | 企业微信群机器人的 Webhook 地址 |

### 钉钉机器人

| 参数 | 说明 |
|------|------|
| Webhook URL | 钉钉群机器人的 Webhook 地址 |
| 签名密钥 | 可选，机器人安全设置中的加签密钥 |

### 飞书机器人

| 参数 | 说明 |
|------|------|
| Webhook URL | 飞书群机器人的 Webhook 地址 |
| 签名密钥 | 可选，机器人安全设置中的签名校验密钥 |

### 邮箱 (SMTP)

| 参数 | 说明 |
|------|------|
| SMTP 服务器 | 邮件服务器地址，如 `smtp.qq.com` |
| SMTP 端口 | 邮件服务器端口，如 465 或 587 |
| 发件邮箱 | 发送通知的邮箱地址 |
| 邮箱密码 | 邮箱密码或授权码 |
| 使用 SSL | 是否启用 SSL 加密连接 |

### 微信公众号

| 参数 | 说明 |
|------|------|
| AppID | 公众号的 AppID |
| AppSecret | 公众号的 AppSecret |
| 模板消息 ID | 模板消息的 Template ID |
| 接收者 OpenID | 接收消息的用户 OpenID |
